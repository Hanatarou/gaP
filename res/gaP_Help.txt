[About]

gaP is a universal DIY (Do It Yourself) style launcher for creating
portable applications on Windows. gaP is based on yaP which is tproli
creation (#1, #2).

Version 2.0.0.0 and newer are a port of gaP from AutoIt to Rust. They read
the same ini files. The source code and the releases are at the gaP
repository (#15).

[How gaP works]

When launching gaP it reads settings from an ini file to what files and
directories to copy and which registry keys to backup etc.. Then launches
the main application and waits until it is closed. When that happens, gaP
saves application settings to the portable directory and restores local
backups.

gaP main features:

* portabilize applications by listing directories, files, registry keys 
  and values in an ini file;
* automatically run the 64bit version of the main application if available;
* create, copy, move and delete files, directories, registry keys and
  values;
* handle x86 and x64 registry entries by using the appropriate switch in
  the registry based functions;
* various checks: administrator rights, multiple instance, OS version, .NET,
  Java and Internet connection;
* request administrator rights if administrator rights are required;
* execute batch files;
* import and export registry keys;
* merge reg files;
* read and write ini files;
* replace strings or lines in text files;
* set environment variables;
* show custom messages;
* run applications;
* create, delete, start and stop services;
* delete the oldest or newest files or folders based on date or name
  (useful to keep backup files or folders under a defined number);
* create symlinks (requires NTFS file system, administrator rights and
  compatible OS);
* register and unregister dll files;
* environment variable and shell folder expansion;
* path, date, text and language macros;
* set file and directory attributes;
* encrypt configuration items using "-crypt" parameter;
* refresh system shell icons;
* kill processes;
* put text on clipboard; and
* clean "MuiCache" and "App Paths" values from registry on demand and
  on close.

[Usage]

Before start, examine the application you are about to portabilize and
find out where does it store settings, how deeply integrates to the
system etc.. This is necessary to be able to tell gaP what directories,
files, registry keys to take care of.

Follow these steps to create a new gaP launcher:

1. Create a new directory ("MyApp", for instance) and put application's files
   to a subdirectory ("MyApp\App", for instance). Use Universal Extractor (#3)
   to get application files if it is an installer or install and uninstall 
   if other methods fail.
   
2. Copy "gaP.exe" to "MyApp" directory and rename it to a custom name 
   ("MyAppPortable.exe", for instance).

3. Run "MyAppPortable.exe" and click Ok to generate a new gaP settings 
   file ("MyAppPortable.ini").

4. Edit "MyAppPortable.ini" and fill the necessary fields.

* Add main application's exe path (application = App\MyAppName.exe); and
* List files, directories, registry keys or values to portabilize.

Refer to the configuration "Configuration" section for ini syntax.

5. Run "MyAppPortable.exe".

Note: if your portable needs advanced logic you can execute custom batch
files with gaP.

[gaP parameters]

gaP currently accepts four parameters:

* -crypt --> opens gaP encryption and decryption interface;
* -license --> opens gaP license interface;
* -about --> opens gaP about interface; and
* -help --> creates a copy of gaP help file in "gaP.exe" 
  root folder.

[Encrypting text]

It is possible to add encrypted text to config files. The purpose is to 
avoid sensitive data in plain text format (passwords, file paths etc.).

Run "gaP.exe" with the "-crypt" parameter and it will open its encryption 
and decryption interface.

As soon as gaP detects an encrypted text in gaP configuration ini it will 
open a password entry dialog to decrypt the text entry.

[Configuration]

Ini sections:

* GENERAL: contains application path, commandline parameters and
  working directory, plus initial system checks;
* BEFORE: items that are run before launching the main application;
* AFTER: items that are run after closing the main application; and
* QUICK REFERENCE: a help section to provide an overview of the
  available items.

Structure of the items:

* Items consist of keyword and value pairs. Values may contain several
  segments separated with the " :: " delimiter;
* If a segment needs to be skipped set its content to "NULL". Optional
  segments are indicated with square brackets;
* Items can be commented out with the ";" character. Comments are
  skipped by gaP; and
* Any keyword followed by a "x86" or "x64" text will be processed only if
  the host OS architecture matches the "x86" or "x64" text.

Examples:

keyword = segment1                                         ; config item with one segment
keyword = segment1 :: segment2 :: segment3                 ; item with three segments
keyword = segment1 :: NULL :: segment3                     ; item with three segments (second segment is empty)
keyword = segment1 [ :: segment2]                          ; item with an optional second segment
; keyword = segment1                                       ; commented item (it will not be processed)
keywordx86 = segment1                                      ; config item with one segment (processed ONLY if host OS architecture is 32 bits)
keywordx64 = segment1 :: segment2 :: segment3              ; item with three segments (processed ONLY if host OS architecture is 64 bits)

Order of the items:

The first item should always be "application" in the GENERAL section.
The order of the items are arbitrary otherwise. Some keywords are
restricted to BEFORE or AFTER sections, these are indicated below.
Keywords used in the wrong sections will show a warning.

Paths:

Paths can be absolute or relative to the launcher. DO NOT add quotes
around them if they contain spaces. Environment variables, shell folders
and gaP macros (see the Variables and macros section) can also be used
when constructing paths.

A %NAME% that is neither a shell folder nor an environment variable is
reported like an undefined {NAME}: The "NAME" variable isn't defined and
can't be used. Batch parameters (%1, %~dp0) and the variables that cmd.exe
expands only at run time (%CD%, %DATE%, %TIME%, %RANDOM%, %ERRORLEVEL%)
are not reported.

On a 64-bit Windows, a path inside the Windows "System32" folder is the
one the main application sees, whatever the build of gaP (x86 or x64) is.

x86 and x64:

The same ini file works with the x86 and with the x64 build of gaP. What
decides the architecture is the main application, not gaP:

* The first segment of "application" is the x86 application and the second
  one is the x64 application. The architecture of the main application is
  the one of the segment that gaP launched;
* The "System32" folder in paths, the "regdll" and "batch" keywords and the
  "!java" and "!dotnet" checks follow the architecture of the main
  application;
* The Registry flag [x86|x64] of the registry keywords is always explicit and
  defaults to "x86", whatever the architecture of gaP or of the application
  is. "x86" is the 32-bit view of the registry (Wow6432Node under
  "HKLM\Software") and "x64" is the 64-bit view. Use "x64" for the keys of
  an x64 application;
* "HKCU\Software" is a single key shared by the two views, so the flag makes
  no difference there, except for the keys that Windows redirects (the ones
  under "HKCU\Software\Classes", like "CLSID"); and
* A keyword followed by "x86" or "x64" ("keywordx64") is processed only if
  the architecture of Windows matches.

Special characters:

Variables can be called by using curly brackets "{" and "}" around their
name. When there is the need to use real curly brackets in text without
calling a variable they must be escaped using an angle bracket "<", for
instance "<{" and "<}".

[Keywords to use in the GENERAL section]

[application]
Description:

Path of the main application to run. Required.

Syntax:

application = Application path x86 :: Application path x64 [ :: Application window state [hide|min|max]]

Examples:

application = C:\Dir\App.exe :: ..\Dir\AppX64.exe
application = %ProgramFiles%\App.exe :: %ProgramFiles%\AppX64.exe :: max
application = %ProgramFiles%\App.exe :: NULL :: max
application = NULL :: %ProgramFiles%\AppX64.exe :: max

Notes:

* On a 64bit OS gaP automatically launches the application set in the
second segment (if available).
* The first segment is the x86 application and the second one is the x64
application: the architecture of the main application is the one of the
segment that gaP launched. On a 32bit OS it is always the first one.
* For an application that exists only as x64 use NULL as the first segment.
* gaP reads the executable and checks that it is for the architecture of the
segment it was set in. An x64 executable in the first segment, or an x86 one
in the second, is an error: gaP shows a message and exits (exit code 2)
before doing anything. A file that is not an executable (a script, a
shortcut) is not checked.
* Both gaP builds (x86 and x64) behave the same way with the same .ini. What
depends on the architecture of the main application, and not on the one of
gaP, is: the "System32" folder in paths, the "regdll" and "batch" keywords
(the 64bit System32 for an x64 application, SysWOW64 for an x86 one) and the
registry view where "!java" and "!dotnet" look for Java and .NET.

[commandline]
Description:

Commandline parameters to pass to the main application.

Syntax:

commandline = Commandline parameters

Examples:

commandline = /nosplash
commandline = --dir="{GAPROOT}\Settings"

Notes:

* None.

[workdir]
Description:

Working directory of the main application.

Syntax:

workdir = Directory path

Examples:

workdir = C:\MyApp
workdir = %Appdata%\MyApplication

Notes:

* Defaults to the main application's directory if not specified otherwise.

[!admin]
Description:

Indicate that administrator rights are required for the main application to run.

Syntax:

!admin = Action number [-1|1|2]

Examples:

!admin = -1                          ; quit if user doesn't have administrator rights (no message)
!admin = 1                           ; start the launcher with administrator rights
!admin = 2                           ; show a message if user is not administrator and quit

Notes:

* None.

[!dotnet]
Description:

Notify the user if the specified .NET version is needed to run the main
application and is not available on the host machine.

Syntax:

!dotnet = .NET version number

Examples:

!dotnet = 4.0
!dotnet = 2.1!

Notes:

* Use an exclamation mark to exit if the specified version is not available;
  and
* The check follows the architecture of the main application: the 32-bit
  .NET Framework for an x86 application and the 64-bit one for an x64
  application (on a 64-bit Windows).

[!java]
Description:

Notify the user if the specified Java version is needed to run the main
application and is not available on the host machine.

Syntax:

!java = Java version number

Examples:

!java = 1.6
!java = 1.7!

Notes:

* Use an exclamation mark to exit if the specified version is not available;
  and
* The check follows the architecture of the main application: the 32-bit
  Java for an x86 application and the 64-bit Java for an x64 application
  (on a 64-bit Windows).

[!multiple]
Description:

Enable or disable multiple instances of the main application.

Syntax:

!multiple = Action number [-1|0|1]

Examples:

!multiple = -1                       ; always disable multiple instances (no dialog)
!multiple = 0                        ; show a dialog asking user what to do
!multiple = 1                        ; always enable multiple instances (no dialog)

Notes:

* If not specified otherwise gaP defaults this option to "0"
  asking user what to do; and
* Any other value is not valid: gaP shows a message and uses "0".

[!online]
Description:

Notify the user that Internet connection is required for the main
application if offline (or vice versa).

Syntax:

!online = Action number [-4|-3|-2|-1|1|2]

Examples:

!online = 1                          ; ask to continue if online status is required (if offline)
!online = 2                          ; show a dialog box that online connection is required and quit (if offline)
!online = -1                         ; quit without a dialog box (if offline)
!online = -2                         ; ask to continue if offline status is required (if online)
!online = -3                         ; show a dialog box that offline connection is required and quit (if online)
!online = -4                         ; quit without a dialog box (if online)

Notes:

* gaP considers the computer online when at least one of its tests (ping
  and TCP connection to well known servers) succeeds.

[!os]
Description:

Notify the user if the current OS version does not meet the main
application's minimum or maximum OS requirement.

Syntax:

!os = OS action code [XP|Vista|7|8|8.1|10|11]

Examples:

!os = Vista                          ; the main application requires Windows Vista or newer
!os = 10                             ; the main application requires Windows 10 or newer
!os = 11                             ; the main application requires Windows 11 or newer
!os = <8.1                           ; the main application requires Windows 8.1 or older

Notes:

* Use the "<" character before the OS action code to
  indicate the maximum OS version;
* Windows 11 is told from Windows 10 by its build number (22000 or newer);
* gaP 2.0.0.0 runs on Windows 10 or newer, so a minimum below 10 is always
  met, but a maximum ("<") is still useful; and
* A value that is not in the list shows a message and the check is skipped.

[!readonly]
Description:

Notify the user that the main application and launcher are running
from a read only drive.

Syntax:

!readonly = Action number [-2|-1|1|2]

Examples:

!readonly = -2                       ; quit without a dialog box (if running from a read only drive)
!readonly = -1                       ; show a dialog box regarding read only drive and quit (if running from a read only drive)
!readonly = 1                        ; show a dialog box regarding read only drive and continue (if running from a read only drive)
!readonly = 2                        ; continue without a dialog box (if running from a read only drive)

Notes:

* If not specified otherwise gaP defaults this option to "1" showing
  a dialog box regarding read only drive and continuing.

[!waitprocess]
Description:

Title (or part of the title) of a window, or name of a process, that should
be closed before executing AFTER items.

Syntax:

!waitprocess = Full or partial window title, or process name

Examples:

!waitprocess = - Notepad++           ; wait for all applications to close having "- Notepad++" in title
!waitprocess = MyTrayApp.exe         ; wait for all processes named "MyTrayApp.exe" (or "MyTrayApp") to end

Notes:

* Some applications are only launchers to other applications and in these
  cases gaP would execute AFTER items right after closing the main application.
  By specifying a process to wait it is possible to run AFTER items only when
  the process terminates;
* The value can be the full title of a window or only part of it. Be careful
  not adding too generic values;
* The value is also compared with the names of the running processes (with or
  without ".exe", upper or lower case, the whole name). This is how an
  application that has no window, such as one that lives in the notification
  area, is waited for; and
* All matching windows and processes should be closed to start executing
  AFTER items.

[Keywords to use in BEFORE and AFTER sections]

[dir]
Description:

Backup, save and restore contents of a directory.

Syntax:

dir = Source directory path :: Target directory path

Examples:

dir = C:\Dir :: SubDir
dir = C:\Dir                         ; Settings subdirectory will be used as target directory

Notes:

* This function works ONLY in the BEFORE section;
* If target directory is missing the "Settings" subdirectory of the
  launcher will be used;
* The name ending in "_backup" is reserved: gaP uses it only while it runs.
  If one is still there when gaP starts, an earlier run did not finish and
  it holds your original data. gaP shows an error listing it and exits
  (exit code 7) before changing anything. Restore it by hand or delete it
  and run gaP again; and
* If the original data can't be saved to "_backup", the item is skipped and
  nothing of it is changed.
* Operations on BEFORE section:
1. backup directory "C:\Dir" to "C:\Dir_backup"
2. create directory "C:\Dir"
3. copy contents of directory "{GAPROOT}\SubDir" to "C:\Dir"
* Operations on AFTER section:
1. copy contents of directory "C:\Dir" to "{GAPROOT}\SubDir"
2. delete directory "C:\Dir"
3. restore directory "C:\Dir_backup" to "C:\Dir"

[file]
Description:

Backup, save and restore a file.

Syntax:

file = Source file path :: Target file or directory path

Examples:

file = %Appdata%\MyFile.ini :: SubDir\MyFile.ini
file = C:\Dir\MyFile.ini :: SubDir
file = C:\Dir\MyFile.ini                                   ; launcher directory will be used as target directory

Notes:

* This function works ONLY in the BEFORE section;
* If the target file or directory is missing the launcher directory
  will be used;
* The name ending in "_backup" is reserved: gaP uses it only while it runs.
  If one is still there when gaP starts, an earlier run did not finish and
  it holds your original data. gaP shows an error listing it and exits
  (exit code 7) before changing anything. Restore it by hand or delete it
  and run gaP again; and
* If the original data can't be saved to "_backup", the item is skipped and
  nothing of it is changed.
* Operations on BEFORE section:
1. backup file "C:\Dir\MyFile.ini" to "C:\Dir\MyFile.ini_backup"
2. copy file "{GAPROOT}\SubDir\MyFile.ini" to directory "C:\Dir"
* Operations on AFTER section:
1. move file "C:\Dir\MyFile.ini" to directory "{GAPROOT}\SubDir"
2. restore file "C:\Dir\MyFile.ini_backup" to "C:\Dir\MyFile.ini"

[regkey]
Description:

Backup, save and restore a registry key.

Syntax:

regkey = Source registry key [ :: Target registry export file or target directory path] [ :: Registry flag [x86|x64]]

Examples:

regkey = HKLM\Software\RegKey :: SubDir\settings.reg       ; save the x86 reg key (Wow6432Node) in "{GAPROOT}\SubDir\settings.reg"
regkey = HKLM\Software\RegKey :: settings.reg :: x64       ; save the x64 reg key in "{GAPROOT}\settings.reg"
regkey = HKLM\Software\RegKey :: SubDir                    ; save the x86 reg key (Wow6432Node) in "{GAPROOT}\SubDir\settings.reg"
regkey = HKLM\Software\RegKey :: NULL :: x64               ; save the x64 reg key in "{GAPROOT}\settings.reg"

Notes:

* This function works ONLY in the BEFORE section;
* If the target registry export file is missing the registry key will
  be exported to "settings.reg" to the launcher's root directory;
* If the Registry flag is not declared it defaults to "x86";
* The name ending in "_backup" is reserved: gaP uses it only while it runs.
  If one is still there when gaP starts, an earlier run did not finish and
  it holds your original data. gaP shows an error listing it and exits
  (exit code 7) before changing anything. Restore it by hand or delete it
  and run gaP again; and
* If the original data can't be saved to "_backup", the item is skipped and
  nothing of it is changed; and
* If the key can't be cleared before the portable settings are imported,
  gaP warns, imports nothing and saves nothing in this run, and the
  original data is put back in the AFTER section.
* Operations on BEFORE section:
1. backup regkey "HKCU\Software\RegKey" to "HKCU\Software\RegKey_backup"
2. import file "settings.reg" to the registry
* Operations on AFTER section:
1. export regkey "HKCU\Software\RegKey" to "settings.reg". The export is
   made to a temporary file that takes the place of "settings.reg" only
   when it worked; if it fails, the previous "settings.reg" is kept, gaP
   shows an error, steps 2 to 5 are skipped and the original data stays
   in "HKCU\Software\RegKey_backup"
2. check that "HKCU\Software\RegKey_backup" can be read; if it can't,
   "HKCU\Software\RegKey" is left as it is and nothing is removed
3. delete the content of regkey "HKCU\Software\RegKey"
4. restore regkey "HKCU\Software\RegKey_backup" to "HKCU\Software\RegKey"
   and delete "HKCU\Software\RegKey_backup"
5. delete empty parent regkeys if regkey is a subkey of "HKCU\Software"
   or "HKLM\Software"

[->dir]
Description:

Copy or move contents of a directory to another directory.

Syntax:

->dir = Source directory path [ :: Target directory path] [ :: copy|move, no overwrite|overwrite]

Examples:

->dir = %Temp%\Dir :: SubDir                               ; copy contents of "%Temp%\Dir" to "{GAPROOT}\SubDir"
<-dir = %Temp%\Dir :: SubDir :: move                       ; move contents of "{GAPROOT}\SubDir" to "%Temp%\Dir"
->dir = C:\Dir :: C:\Dir_old :: no overwrite               ; backup dir to "C:\Dir_old" (copy, skip existing)
<-dir = C:\Dir :: C:\Dir_backup :: move                    ; restore dir "C:\Dir_backup" to "C:\Dir" (move)
->dir = %Desktop%\OldDir :: %Desktop%\NewDir :: move       ; rename "OldDir" to "NewDir" on Desktop

Notes:

* Use "<-dir" keyword to reverse direction;
* Use the "move" flag to move directory contents instead of "copy".
  After moving the source directory is deleted;
* Use the "no overwrite" flag to skip operation if the target already
  exists;
* To rename a directory move directory contents to a different
  directory on the same path;
* An empty target directory (NULL) defaults to "Settings" subdirectory
  of the launcher;
* If source and target are equal no operation will be done; and
* When "move, overwrite" replaces an existing target, the old content waits
  next to it as "<target>.gap_old" until the move is done, and then as
  "<target>.gap_del" until it is deleted; a run that was interrupted is
  finished the next time. Do not use those two names (nor "<target>.gap_del"
  followed by digits) for your own directories.

[->file]
Description:

Copy or move a file.

Syntax:

->file = Source file path [ :: Target file or directory path] [ :: copy|move, no overwrite|overwrite]

Examples:

->file = C:\File.ini :: Dir                                ; copy "C:\File.ini" to "{GAPROOT}\Dir"
->file = C:\File.ini :: Dir\File.ini :: move               ; move "C:\File.ini" to "{GAPROOT}\Dir"
<-file = C:\File.ini :: Dir\File.ini :: move               ; move "{GAPROOT}\Dir\File.ini" to "C:\"
->file = %Appdata%\settings.xml                            ; copy "%Appdata%\settings.xml" to launcher directory
<-file = C:\a.7z :: NULL :: no overwrite                   ; copy "{GAPROOT}\a.7z" to "C:\" (skip existing)
->file = File.txt :: Todo.txt :: move                      ; rename "File.txt" to "Todo.txt"

Notes:

* Use "<-file" keyword to reverse direction;
* Use the "move" flag to move file instead of copy. After moving the
  source file is deleted;
* Use the "no overwrite" flag to skip operation if the target already
  exists;
* If target is a directory then the target filename will be the same
  as the source filename;
* To rename a file move file to a different filename on the same path;
* An empty target (NULL) defaults to launcher root directory; and
* If source and target are equal no operation will be done.

<-regkey = HKCU\Software\A :: HKCU\Software\B :: move                          ; move contents of regkey B to A
->regkey = HKCU\Software\OldKey :: HKCU\Software\NewKey :: move                ; rename regkey

Notes:

* Use the "move" flag to move registry key contents instead of copy.
  After moving the source key is deleted;
* If the Registry flag is not declared it defaults to "x86";
* To rename a registry key move key contents to a different key under
  the same key; and
* If the target registry key is left empty or source and target are
  equal no operation will be done.

[Variables and macros]

The smallest macro is replaced first, so a macro can be inside the name of
another one, eg. "{PREFIX_{LANGCODE}}". A macro is replaced by its value once,
and the value is never searched for macros again. Text that comes from outside the gaP ini (clipboard, dialogs,
the command line, files read with "iniread") is kept as it is, even if it has
"{" and "}" in it. The value of a "uservar" is written in the gaP ini, so its
macros are expanded when the variable is defined.

{GAPROOT} absolute path of the launcher's directory
{EXEPATH} absolute path of the main application's directory
{APPEXE} absolute path of the main application
{DRIVE} current drive letter of the launcher, eg. "D"
{JAVAEXE} absolute path to installed Java executable (javaw.exe). It is the
          first one found (64-bit Java before 32-bit), whatever the
          architecture of the main application is
{USERFILE} browse file dialog to dynamically add filepath
{USERDIR} browse directory dialog to dynamically add path

[Text macros]

[Frequently Asked Questions - FAQ]

Q: I don't understand a thing!
A: Though gaP is intended to be easy to use it is not for beginners. If you are looking
   for ready made portable applications visit The Portable Freeware Collection (#5),
   Lupo PenSuite (#6), PortableApps.com (#7), LiberKey (#8), WinPenPack (#9) or other
   portable collection sites.

Q: How can I update gaP-ped portables?
A: Manually update main application files even if an auto update feature is
   available. Otherwise the main application may restart itself and leave
   settings in the system. Also check whether the new version saves
   settings to the same locations - if not, change the configuration ini
   accordingly.

Q: Is there any directory structure convention to follow?
A: No. gaP needs only the config file ("LauncherName.ini" or "gaP.ini") to be
   next to the launcher executable. Application and settings files can be anywhere.

Q: How do I change from the x86 to the x64 build of gaP (or the other way)?
A: Replace "gaP.exe" with the one of the other build and keep the same name:
   the ini file has the same name and works with both builds. The main
   application is chosen by the "application" key, not by the build of gaP.

Q: How can I change "gaP.exe" icon?
A: Use a 3rd party software like PE Icon Changer (#10) or Greenfish Icon Editor Pro (#11).

Q: Is gaP PortableApps format compatible?
A: gaP is not designed to be compatible with PA but creating the extra
   dirs/files that PA requires it can be done.

Q: Can I use UPX (#12) to further reduce the launcher size?
A: No. The releases are already built for size and some AV software may
   flag an executable compressed with UPX as malicious.

Q: Can I use "HKCU" and "HKEY_CURRENT_USER" interchangeably?
A: Yes, just like "HKLM" and "HKCR" as well.

Q: Can gaP show a splash screen?
A: No. This feature is not planned.

Q: Will gaP create a directory if the parent directory is not available?
A: Yes, gaP creates a directory tree.

Q: Can I use "..\" or nested directories in paths?
A: Yes. "+file = ..\Subdir1\Subdir2\MyFile.txt" will work.

Q: What programming language is gaP written in? Is the source code available?
A: Version 2.0.0.0 and newer are written in Rust and the source code is
   available under the MIT license at the gaP repository (#15). Versions up
   to 1.1.5.0 were written in AutoIt (#13).

Q: Where can I submit a new example configuration or report a bug?
A: Visit the gaP forum topic at The Portable Freeware Collection (#14) or
   the gaP repository (#15).

Q: I get the message "The "NAME" variable isn't defined and can't be used."
A: NAME is written as {NAME} or %NAME% in the ini file but it is not a gaP
   macro, a user variable ("uservar", "iniread", "stringreplace"), a shell
   folder or an environment variable. Check the spelling.

Q: I get the message "Administrator rights may be required."
A: A registry operation could not be done and gaP is not running as
   administrator. Set "!admin = 1" in the GENERAL section to start the
   launcher with administrator rights.
